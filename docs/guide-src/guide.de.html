1. Was LegatorOCR ist

LegatorOCR verwandelt Scans oder Fotos von Seiten in ein sauberes PDF mit durchsuchbarem Text. Es löst dasselbe Problem wie ScanTailor (Seiten trennen, geraderichten, beschneiden, bereinigen), fügt aber PDF-Export und OCR hinzu. Es ist in Rust geschrieben, mit eigenem Code, wobei jede Stufe eine Lehrbuchtechnik ist. Es läuft lokal, ohne Konto und ohne dass die Seiten ins Internet gesendet werden. Lizenz: MIT.

Es gibt zwei Arbeitsweisen, mit denselben Engines darunter:

  • Die grafische Oberfläche (legatorocr-gui): Sie fügen Seiten hinzu, sehen Original und Ergebnis nebeneinander, korrigieren Seite für Seite und exportieren.

  • Die Kommandozeile (legatorocr): für große Stapel, für die Automatisierung und für Optionen, die die Oberfläche nicht zeigt.

Was es leistet

  • trennt Doppelseiten-Bögen in zwei Seiten, richtet schiefe Seiten gerade und beschneidet die Ränder;

  • bereinigt Hintergrund, Flecken, Lochungen, Finger am Rand und Formularlinien;

  • schreibt PDF (einschließlich PDF/A zur Archivierung) oder Bilder, mit OCR auf Rumänisch und in 7 weiteren Sprachen;

  • erzeugt auch einfachen Text (.txt) und hOCR und kann das PDF signieren oder mit einem Zeitstempel versehen.

Was es nicht leistet (oder nicht nachgewiesen wurde)

  • Es ist eine Testversion ({{VERSION}}). Sie wurde vom Autor und seinem Assistenten nur unter Linux ausgeführt; Windows, macOS und arm64-Prozessoren wurden von Menschen nicht ausprobiert.

  • Die OCR-Genauigkeit wurde an 8 guten Seiten einer einzigen rumänischen Zeitschrift gemessen, gegenüber einem Referenztext, der von einem anderen Programm erzeugt und nicht von Menschen korrigiert wurde. Betrachten Sie sie nicht als Garantie für andere Druckarten.

  • Die OCR kann Fehler machen: Prüfen Sie wichtige Seiten stichprobenartig.

2. Installation und erster Start

Laden Sie das Archiv für Ihr System von der Seite der Releases des Repositorys chiuta/LegatorOCR herunter. Jedes Archiv hat eine Datei .sha256 zur Überprüfung.

SystemDateiHinweise

Sie können auch aus dem Quellcode bauen: cargo build --release (erfordert Rust 1.95 oder neuer).

OCR

Das Programm hat eine eigene OCR-Engine, die ohne Installation funktioniert. Optional können Sie Tesseract installieren, ein separates Programm, das LegatorOCR automatisch verwendet, wenn es vorhanden ist und die angeforderte Sprache hat:

  • Linux (Debian/Ubuntu): sudo apt install tesseract-ocr tesseract-ocr-ron

  • macOS: brew install tesseract tesseract-lang

  • Windows: winget install UB-Mannheim.TesseractOCR und es zum PATH hinzufügen

Das rumänische Modell aus den Paketen apt und brew ist die kleine Variante („fast“). Die Variante „best“ wird manuell heruntergeladen und mit --tessdata DIR angegeben. Welche Ihre Seiten besser liest, wurde nicht gemessen.

Die Installation prüfen

Führen Sie legatorocr --doctor aus. Es zeigt die Version, die native OCR-Engine, Tesseract und die Sprachmodelle an, danach Hilfswerkzeuge (pdftoppm, gs, qpdf, mutool). Das Ergebnis „missing“ bei einem optionalen Werkzeug ist kein Fehler; die Meldung darunter sagt, ob es gebraucht wird. Wenn etwas nicht funktioniert, kopieren Sie die gesamte Ausgabe des Befehls in einen Bericht (siehe Abschnitt 10).

Die Ausgabe des Befehls legatorocr --doctor (pre.20, Linux, in einem echten Terminal; ebenso alle Terminal-Screenshots im Handbuch, mit xterm aufgenommen): „missing“ bei mutool ist ein optionales Werkzeug, kein Fehler.

3. Der Arbeitsablauf, Schritt für Schritt

Für jede Seite durchläuft das Programm die folgenden Stufen in dieser Reihenfolge. Die Analyse erfolgt auf einer Kopie von etwa 150 dpi, und das Ergebnis wird anschließend auf den Scan in seiner vollen Auflösung angewendet.

  1. Orientierung. Liegende Seiten (Vierteldrehung) werden anhand der Buchstaben der Seite erkannt: Eine Seite mit Bildern oder mit wenigen Wörtern wird von diesem Test nicht gedreht. Für die genaue Richtung kann Tesseract (OSD) oder die manuelle Drehung verwendet werden.

  2. Blatt trennen. Ein Querformat-Blatt mit zwei Seiten wird in der Mitte geschnitten, am leeren Band in der Mitte. Das kann automatisch erfolgen, in der Mitte oder ausgeschaltet sein.

  3. Geraderichten. Der Neigungswinkel wird aus den Textzeilen geschätzt, und die Seite wird zurückgedreht. Der Winkel kann manuell festgelegt werden.

  4. Inhaltsrahmen. Der Bereich mit Text und Bildern wird gefunden; Scannerschatten und Staub werden ignoriert. Alles außerhalb wird in der Papierfarbe neu übermalt.

  5. Ränder und Größe. Ränder in Millimetern, optional eine feste Seitengröße oder dieselbe Größe für das ganze Buch.

  6. Gekrümmte Zeilen begradigen (optional). Für volle Buchseiten mit zum Buchrücken hin gekrümmten Zeilen.

  7. Beleuchtung (optional). Gleicht den ungleichmäßigen Hintergrund aus.

  8. Bereinigen und Binarisieren. Entfernt Flecken, Lochungen, Finger, Linien; danach Schwarzweiß, Grau, Farbe, gemischt oder hybrid.

  9. PDF und OCR. Das PDF (oder die Bilder) wird geschrieben und, wenn angehakt, die Textebene.

Automatisches Geraderichten: ein um 3,5° geneigter Scan (von mir erzeugtes Testblatt) und das Ergebnis; das Programm hat -3,50° gemessen.

Arbeitsregeln, die Zeit sparen

  • Legen Sie zuerst die richtige Auflösung fest (meist 300 dpi für Text). Das Programm liest sie aus dem Bild, wenn sie zwischen 150 und 1200 liegt; andernfalls nimmt es 300 an.

  • Wählen Sie ein zum Material passendes Profil (Abschnitt 6), bevor Sie an einzelnen Einstellungen drehen.

  • Verarbeiten Sie 10–20 Seiten als Probe, prüfen Sie das Ergebnis und starten Sie dann den großen Stapel.

  • Die Oberfläche markiert Seiten „Zu prüfen“ (leere Seite, Schräglage am Grenzwert, nichts gefunden, Inhalt am Rand klebend). Gehen Sie sie mit der Schaltfläche „Nächste“ durch.

Die Seitenliste

Eine komplett weiße Seite wird automatisch markiert: ein orangefarbener Punkt in der Liste und das Feld „Zu prüfen: 1“ mit der Schaltfläche „Nächste“.

Ziehen Sie Bilder, PDFs, Archive oder einen Ordner hinein, oder drücken Sie „Hinzufügen“. Die Schaltflächen Nach oben/Nach unten ändern die Reihenfolge, „Entfernen“ nimmt die gewählte Seite heraus, „Leeren“ nimmt alles heraus. Die Reihenfolge in der Liste ist die Reihenfolge im PDF.

Die Vorschau

  • Nebeneinander / Original / Bearbeitet wählt, was Sie sehen. Die Zonen werden auf dem Original gezeichnet; der Inhaltsrahmen wird auf Bearbeitet korrigiert.

  • Einpassen vergrößert oder verkleinert das Bild, damit es passt. Der Zoomregler (0,2×–4×) erscheint nur, wenn Einpassen nicht angehakt ist.

    Bei nicht angehaktem „Einpassen“ erscheint der Zoomregler (hier 1,00×).

Die Leiste „Diese Seite“

Hier korrigieren Sie nur die gewählte Seite: Drehung nach links oder rechts um 90°, Schritte von ±45°, manuelle Schräglage, Modus der Blatttrennung (Standard, automatisch, in der Mitte, aus), Inhaltsrahmen in Millimetern (links, oben, rechts, unten; positive Werte vergrößern ihn) und „Zurücksetzen“. Rückgängig und Wiederholen (Ctrl+Z, Ctrl+Y) gelten für alle diese Befehle, nicht nur für Zonen.

Manuelles Drehen sperrt die automatische Orientierung (seit pre.18): Nachdem Sie eine Drehtaste oder ±45° gedrückt haben, wird die Seite weder von der Erkennung liegender Seiten noch von OSD gedreht, nicht einmal bei 0°. „Zurücksetzen“ gibt ihr die automatische Orientierung zurück. Wenn eine Seite mit Bildern von Anfang an falsch gedreht wird, drücken Sie die Drehung viermal (oder haken Sie in den Einstellungen unter Eingabe „Ausrichtung per OCR (OSD)“ und „Gedrehte Seiten erkennen“ ab).

Vier Klicks hintereinander auf „90° nach rechts drehen“: 90°, 180°, 270°, dann zurück auf 0°, ohne Sprünge. Screenshot pre.18 unter Linux. Unter Windows 11 konnte ich es nicht prüfen.

Rückgängig (die Schaltfläche) und Ctrl+Z (bei Fenster im Vordergrund) entfernen die zuletzt gezeichnete Zone. Im Fenster geprüft.

„Punktraster“ bei Hilfslinie: 5 Linien mit je 7 Punkten, über den Textzeilen.

Punktraster (bei Hilfslinie) fügt 5 Linien mit je 7 Punkten hinzu, deren Punkte Sie auf die Textzeilen ziehen. Ein zweiter Klick auf die Schaltfläche fügt dasselbe Raster nicht ein zweites Mal hinzu. Wenn Sie bereits Punkte verschoben haben, wird ein neues Raster zusätzlich zum verschobenen hinzugefügt.

Arbeitsbereich (seit der Ausgabe pre.18): Sie ziehen ein Rechteck auf dem Original; alles außerhalb wird vor jeder Messung in der Papierfarbe übermalt, ein dunkler Rand oder die Nachbarseite spielen also keine Rolle mehr. Rechtsklick auf das Original entfernt ihn. In der Kommandozeile: --work-area X,Y,L,H (Millimeter).

Schnittlinie (seit der Ausgabe pre.18): Mit Klick oder Ziehen auf dem Original verschieben Sie die senkrechte orangefarbene Linie; das Doppelblatt wird dort geschnitten, nicht in der Mitte oder am Bund. Ab pre.21 funktioniert das bei jeder Drehung; bei um 90° oder 270° gedrehten Blättern schneidet die Linie waagerecht, und die Seiten kommen untereinander heraus (die linke Seite des Originals zuerst). Rechtsklick entfernt sie. In der Kommandozeile: --cut-at 0.45.

Inhaltsrahmen (das gleichnamige Häkchen) zeigt auf der verarbeiteten Seite einen grünen Rahmen an. Sie ziehen an den Seiten, um den beibehaltenen Bereich zu erweitern oder zu verengen. Bei einem in zwei Seiten geschnittenen Blatt ändert sich nur die Seite, auf der man den Rahmen zieht.

Der Inhaltsrahmen (grüner Rahmen) auf der verarbeiteten Seite.

Verzogene Seiten, schräger Schnitt und Einstellungen pro Seite

Drei Hilfen für von Hand fotografierte Blätter:

  • Schräge Schnittlinie. Mit „Löschzonen auf dem Original zeichnen“ und dem Typ Schnittlinie neigt der Regler „Neigung der Linie“ (−20° bis 20°) die Linie; jede Seite behält ihre Seite der schrägen Linie, die andere Seite wird mit der Papierfarbe übermalt. Rechtsklick auf die Linie löscht sie und setzt die Neigung auf null. Auf der Kommandozeile: --cut-angle GRAD.
  • Trapezkorrektur. Zwei Regler in der Leiste „Diese Seite“ („Trapez oben–unten“, „Trapez links–rechts“, ±30 %) richten ein schräg fotografiertes Blatt vor dem Schnitt gerade. Die Schaltfläche Auto-Trapez (nach dem Teilen der Seiten) misst jede Seite — Neigung der Textzeilen und Textbreite oben und unten — und merkt sich eine Korrektur nur für diese Seite. Sie ist absichtlich vorsichtig: bei zu wenigen Zeilen oder widersprüchlichen Messungen bleibt die Seite unverändert. Das Ergebnis prüfen, Rückgängig griffbereit. Die Schaltflächen −45°/+45° bleiben. Auf der Kommandozeile: --keystone-v und --keystone-h (Prozent).
  • Einstellungen pro Seite. „Einstellungen für: Alle Seiten / Nur diese Seite“ über Ausgabe und Bereinigung wendet Ausgabemodus, Schwelle, Fleckenentfernung und die übrigen Bereinigungseinstellungen auf eine einzelne Seite eines geschnittenen Blatts an; der grüne Inhaltsrahmen ändert nur die Seite, auf der er gezogen wird. In einem Projekt: page1.SCHLÜSSEL = WERT / page2.SCHLÜSSEL = WERT unter [sheet]. Ein Klick auf eine verarbeitete Seite wählt sie aus (blauer Rahmen): Ausgabemodus (Grau, Schwarzweiß, Gemischt), Bereinigung, Trapezkorrektur, der grüne Rahmen und die OCR-Stifte wirken dann nur auf diese Seite. Gezeichnete OCR-Zonen bleiben bei dieser Seite (page1.page_ocr_zones, page_ocr_ignore).

Die Leiste unter der Vorschau enthält den Inhaltsrahmen, die OCR-Stifte und den Auto-OCR-Stift (getrennt für linke und rechte Seite): er setzt die OCR-Zone auf den Inhalt dieser Seite.

Die Seitenformate umfassen jetzt A2–A6, B3–B6, Letter, Legal und Tabloid (--page-size kennt dieselben Namen). OCR-Stifte auf verarbeiteten Seiten: grün (OCR-Zone), rot (ignorierter Bereich), violett (Tabelle, als ein Block zeilenweise gelesen; --ocr-zone X,Y,W,H#table).

Die Einstellungen rechts

Sie sind nach Abschnitten gruppiert: Eingabe, Geometrie, Ausgabe, Bereinigung, PDF, OCR, dazu die Profile. Abschnitt 6 erklärt, was jede bewirkt.

Der Abschnitt Bereinigung in den Einstellungen, aufgeklappt: Negativ-Scans invertieren, Auto-Kontrast, Perspektive, Lochungen entfernen, Löschbereiche als Zahlen.

Die Liste „Profil“ in den Einstellungen (die eingebauten Profile; Ihre eigenen erscheinen an derselben Stelle nach „Profil speichern“).

Alle Optionen und das Benutzerhandbuch

Die Schaltfläche Alle Optionen… in der oberen Leiste öffnet ein Fenster mit allen Optionen der Kommandozeile (über 200), nach Themen gruppiert: Seiten und Reihenfolge; Geraderichten, Beschneiden und Bereinigen; Ausgaben (PDF, Bilder, Dokumente); OCR und Text; Archivierung, Signatur und Prüfung; Suchen und Vergleichen; Stapel, System und Module. Die Liste wird direkt aus dem Kommandozeilenprogramm gelesen, das mit dem Fenster ausgeliefert wird, und passt daher immer zu der Ausgabe, die Sie haben.

Das Fenster „Alle Optionen“ mit geöffneter Gruppe „Seiten und Reihenfolge“, angehakten --duplex-adf und --dry-run und dem Ergebnis des Laufs: die Reihenfolge, in der die sechs Seiten des Stapels verarbeitet würden (von mir erstellte Testseiten).

  • Suchen nach Namen (pdf, dry) oder nach einem Wort der Beschreibung; Gruppen mit Treffern öffnen sich von selbst. „Nur gewählte“ zeigt, was Sie angehakt oder ausgefüllt haben.

  • Leere Felder werden nicht gesendet: Eine Option mit Wert kommt nur dann in den Befehl, wenn Sie etwas eintragen (oder aus der Liste wählen). Die Schaltfläche Wählen… öffnet den Datei- oder Ordnerdialog. Bei Optionen, die sich wiederholen lassen (zum Beispiel --erase), schreiben Sie einen Wert pro Zeile.

  • Seiten und Einstellungen des Fensters verwenden (standardmäßig angehakt): Der Befehl erhält die geladenen Seiten mit den Anpassungen jeder einzelnen über ein temporäres Projekt. Die Verarbeitungseinstellungen des Hauptfensters (Geraderichten, Beschneiden, Bereinigen) haben Vorrang; hier ergänzen Sie die Ausgaben und die Spezialfunktionen. Haken Sie es ab für Befehle ohne Seiten (--doctor, --verify-sums) oder schreiben Sie die Eingabedateien in „Weitere Argumente“.

  • Entsprechender Befehl wird aktualisiert, während Sie wählen; Sie können ihn kopieren und im Terminal oder in Skripten verwenden. Ausführen führt ihn aus und zeigt das Ergebnis darunter; Stopp bricht ihn ab. Relative Pfade beziehen sich auf Ihren persönlichen Ordner.

  • Die Beschreibungen der Optionen sind auf Englisch, wie in der Kommandozeile; der Rest des Fensters ist in der gewählten Sprache.

Das Menü Hilfe enthält den Link zu diesem Handbuch: Benutzerhandbuch (online, immer aktuell) öffnet die neueste auf legatorocr.chiuta.ro veröffentlichte Version, und Handbuch dieser Ausgabe (erscheint, wenn die PDF-Datei neben dem Programm liegt, wie in den veröffentlichten Archiven) öffnet die mit dem Programm ausgelieferte Kopie. Das Handbuch wird bei jeder Ausgabe neu erstellt, und die Veröffentlichung einer Ausgabe wird angehalten, wenn das Handbuch ihre Version nicht nennt.

Geprüft: das Fenster, die Suche, das Anhaken, das Ausführen eines Befehls mit den Seiten des Fensters (der Screenshot oben) und das Öffnen des Menüs Hilfe, unter Linux, auf einem virtuellen Bildschirm. Nicht geprüft: Windows, macOS und arm64; das tatsächliche Öffnen des Handbuchs in einem Browser (ich habe nur das Menü geprüft); die Dialoge „Wählen…“; die Übersetzungen der neuen Texte des Fensters (automatisch geschrieben).

5. Die Kommandozeile: Rezepte für häufige Aufgaben

Allgemeine Syntax: legatorocr EINGABEN... [Optionen]. Eingaben können Bilder (PNG, JPEG, TIFF, BMP), gescannte PDFs oder ein Ordner sein. legatorocr --help listet alle Optionen auf; --list-profiles zeigt die Profile. Die Optionen in den Rezepten werden vor jeder Ausgabe automatisch geprüft, sie existieren also wirklich; die Rezepte selbst wurden nicht alle an echtem Material ausprobiert.

Gescanntes Buch → PDF mit durchsuchbarem Text

legatorocr scans/*.png --profile book-bw --ocr --lang ron --pdf carte.pdf --pdfa --txt carte.txt -o pages

--pdfa schreibt PDF/A-2b zur Archivierung, und --txt speichert auch den Text. -o pages ist der Ordner für die verarbeiteten Bilder.

Das Rezept an 4 Testdateien: 6 Seiten in carte.pdf. Mit --pdfa schreibt das Programm PDF/A-2b.

Handyfotos → saubere Seiten

legatorocr photos/*.jpg --profile phone-photos --pdf pagini.pdf -o pages

Das Profil gleicht das Licht an, korrigiert die Perspektive, löscht den Hintergrund um die Seite (--trim-background), schneidet aufgeschlagene Bücher in der Mitte, erweitert den Bereich der Schräglage und entfernt Finger, ohne den Text zu berühren. Eine Seite, die ohne Text herauskommt, wird ein zweites Mal gelesen, und zwar nur auf ihrem Inhalt. Für einheitliche Seiten auf A4 mit vergrößertem Text verwenden Sie --profile phone-photos-a4. Mehrere Fotos derselben Seite lassen sich zuerst mit --fuse-frames kombinieren (hilft bei starkem Rauschen; bei mäßigem Rauschen nicht). Die Option erhält eine Ausgabedatei: legatorocr poza1.jpg poza2.jpg poza3.jpg --fuse-frames pagina.png, danach verarbeiten Sie pagina.png wie gewohnt; das erste Foto ist die Referenz.

--fuse-frames mit drei Fotos derselben Seite: richtet sie aus und schreibt fused.png aus 3 von 3 Bildern.

Archivkopie mit Integritätsnachweis

legatorocr scans/*.png --profile registre-manuscrise --ocr --lang ron --pdf registru.pdf --pdfa --checksums --archive-package registru-arhiva -o pages
legatorocr --verify-sums registru-arhiva/SHA256SUMS.txt

Das Paket bewahrt die Originale, das Projekt, die OCR-Wörter mit Konfidenz, die Ausgaben und eine RUN.txt auf, die sagt, wie die Arbeit wieder aufgenommen wird. Für Kopien auf andere Datenträger: --backup-from und --backup-to.

Das erstellte und geprüfte Archivpaket: „5 ok, 0 mismatched, 0 missing“.

Namen und Nummern vor dem Teilen schwärzen

legatorocr scan.png --ocr --lang ron --redact email,phone-ro --format none --pdf redactat.pdf

Die gefundenen Wörter werden im Bild geschwärzt und aus dem Text entfernt. Prüfen Sie das Ergebnis mit eigenen Augen: Ein Wort, das die OCR nicht erkannt hat, wird nicht verborgen.

Echtes Ergebnis: Die Telefonnummer wurde verborgen, die E-Mail-Adresse aber NICHT, weil die OCR „@“ als „G“ gelesen hat (ion.popescuGexample.com) und das E-Mail-Muster nicht gepasst hat. Deshalb müssen Sie das Ergebnis mit eigenen Augen prüfen. Ab pre.20 schreibt das Programm am Ende, wie viele Wörter jedes Muster abgedeckt hat, und warnt, wenn ein Muster nichts gefunden hat oder wenn im Text Wörter übrig geblieben sind, die wie Adressen oder lange Nummern aussehen, genau wie im Screenshot oben.

Großer Stapel auf mehreren Rechnern

legatorocr scans/*.png --shard 1/3 --profile book-bw --pdf part1.pdf -o pages1
legatorocr --merge-pdf part1.pdf part2.pdf part3.pdf --pdf carte.pdf

Führen Sie auf jedem Rechner dieselbe Liste aus, mit einem anderen --shard. Bei wenig Speicher: --max-memory 500. Für unbekannte oder feindliche Dateien: --isolate-decoders.

Der in zwei Teile geteilte Stapel (--shard 1/2 und 2/2) und danach mit --merge-pdf zusammengefügt.

Ein PDF signieren

LEGATOROCR_P12_PASS=... legatorocr --sign-pdf registru.pdf --sign-p12 certificat.p12 --sign-name "Nume"
legatorocr --verify-pdf-signatures registru.signed.pdf --sign-ca ca.pem

Die rechtliche Stufe der Signatur ist die Ihres Zertifikats. Das Passwort des Zertifikats wird über die Umgebungsvariable übergeben, nicht in der Kommandozeile. Der Zeitstempel (--sign-timestamp) wurde nur mit einer lokalen Stelle über HTTP geprüft, nicht mit einer echten über HTTPS.

Signieren und Prüfen mit einem von mir erstellten Testzertifikat (kein echtes Zertifikat). „time stamp inside: none“: Ich habe keinen Zeitstempel angefordert.

Stapel vom Einzug gescannt, Reihenfolge und Seitenbereich

Viele Scanner mit Einzug lassen den Stapel einmal pro Seite durchlaufen: zuerst alle Vorderseiten (1, 3, 5…), dann alle Rückseiten in umgekehrter Reihenfolge (6, 4, 2). Die Dateien kommen in der Reihenfolge des Scannens heraus, nicht in der des Buches. --duplex-adf bringt sie in Lesereihenfolge: Vorderseite 1, Rückseite 1, Vorderseite 2, Rückseite 2… Die Anzahl der Seiten muss gerade sein (andernfalls bricht das Programm mit einer Meldung ab).

Sechs Dateien in der Reihenfolge des Scannens (scan_001 … scan_006). --dry-run zeigt die Reihenfolge, in der sie verarbeitet würden, und welche Dateien geschrieben würden, und hält dann an, ohne etwas zu verarbeiten: scan_006 landet auf Platz 2, scan_005 auf Platz 4.

Derselbe Befehl ohne --dry-run, mit nativer OCR: Der Text kommt in der Reihenfolge „Pagina 1 … Pagina 6“ heraus (von mir erstellte Testseiten, kein echtes Buch).

Weitere Optionen zu Reihenfolge und Auswahl (kombinierbar; der Bereich bezieht sich auf die Nummerierung der Eingabedateien, ab 1):

  • --pages 1-10,15,20-: behält nur die angegebenen Seiten; 20- bedeutet „ab 20 bis zum Ende“. Funktioniert auch bei Seiten aus PDFs oder aus mehrseitigen TIFF-Blättern.

  • --reverse: kehrt die Reihenfolge um (Stapel, der von der letzten Seite an gescannt wurde).

  • --dry-run: prüft einen großen Stapel vor dem langen Lauf.

Geprüft: die Reihenfolge und der Bereich mit automatischen Tests und mit sechs Testseiten; einen echten Scanner mit Einzug habe ich nicht ausprobiert. Die Optionen lassen sich auch im Fenster unter „Alle Optionen…“ wählen (Abschnitt 4).

Sauberer Text: eigene Korrekturen, Kopfzeilen und Cedilla

Für die Dateien .txt und .docx (die Textebene im PDF, hOCR und JSON behalten die gelesenen Wörter unverändert):

  • --clean-text: ș und ț mit Komma darunter, am Zeilenende getrennte Wörter zusammengefügt (mit beibehaltenem Bindestrich, wenn die beiden Hälften Wörter aus der Liste sind und das einfache Zusammenfügen keines ist), typografische Anführungszeichen, Leerzeichen neben Satzzeichen. --cedilla schreibt stattdessen ş und ţ, für Programme und Schriften, die die Buchstaben mit Komma nicht kennen.

  • --find-replace DATEI: Ihre eigenen Korrekturen, eine pro Zeile, falsch => richtig. Zeilen, die mit # beginnen, sind Kommentare. Es passen nur ganze Wörter (Ion => Ioan berührt „Ionescu“ nicht), und sie werden in der Reihenfolge der Datei nach --clean-text angewendet. Nützlich für Eigennamen, Abkürzungen oder einen Stempel, den die Engine immer gleich falsch liest.

  • --drop-running-heads: lässt Kopfzeilen, Fußzeilen und gedruckte Seitenzahlen weg: die erste oder letzte Zeile einer Seite, die sich auf mindestens der Hälfte der Seiten wiederholt (Ziffern zählen nicht); es sind mindestens vier Seiten nötig. Die entfernten Zeilen werden auf stderr aufgelistet, damit Sie sehen, was weggegangen ist.

Die Regeldatei (erster Block) und dieselben zwei Zeilen von der Testseite gelesen ohne und mit --find-replace: „Ionescu“ wurde zu „Ionescu-Vale“ und „ha“ wurde zu „hectare“.

Bei sechs Testseiten mit der Kopfzeile „Anuarul Văii Mari“ und einer Nummer hat das Programm sechs Kopfzeilen entfernt; der Text beginnt direkt mit „Pagina 1“. Achtung: Die Regel entfernt jede erste/letzte Zeile, die sich wiederholt, bei einem Buch, in dem die letzte Zeile jeder Seite ähnlich aussieht (zum Beispiel „Poziția în raft: 14“), würden also auch diese Zeilen verschwinden; deshalb werden sie aufgelistet. Die Funktion wurde mit Tests und an einigen Seiten geprüft, nicht an einem großen Satz von Büchern.

Die Formate der Textfelder

Diese Felder gibt es in den Einstellungen, aber es ist einfacher, auf dem Original zu zeichnen (Abschnitt 4):

  • Löschbereiche und Bildbereiche: x,y,b,h in Millimetern von der oberen linken Ecke der Seite. Mehrere Bereiche trennt man mit Semikolon: 10,20,30,40;50,60,20,20. Höchstens 64; Breite und Höhe müssen positiv sein. Ist die Form falsch, wird das Feld rot.

  • Hilfslinien zum Begradigen: x,y x,y x,y;x,y x,y x,y, mit Bruchteilen zwischen 0 und 1 der bereits geradegerückten Seite (0,0 = obere linke Ecke). Jede Linie hat mindestens zwei Punkte; insgesamt höchstens 64 Linien.

  • In der Kommandozeile: --erase X,Y,W,H (wiederholbar) und --dewarp-guide "X,Y X,Y …" (wiederholbar).

7. OCR: Engines, Sprachen und Genauigkeit

Das Häkchen „Durchsuchbarer Text (OCR) im PDF“ (oder --ocr in der Kommandozeile) fügt über dem Bild eine unsichtbare Textebene hinzu. Die Sprache wird unter „Erkennungssprachen“ gewählt (oder --lang ron); sie kann kombiniert werden, zum Beispiel ron+eng. Die Sprachen der Oberfläche und der eigenen Engine: Rumänisch, Englisch, Französisch, Italienisch, Spanisch, Portugiesisch, Deutsch, Ungarisch.

Der Abschnitt OCR in den Einstellungen: das Häkchen „Durchsuchbarer Text (OCR) im PDF“, die erkannten Sprachen (die bei Tesseract installierten) und der Segmentierungsmodus. Im Screenshot war Tesseract 5.3.4 installiert, daher erscheinen alle seine Sprachen; die Wahl ron habe ich in der nächsten Abbildung verwendet.

Bei angehaktem OCR erscheinen auch „Text zusätzlich speichern (.txt)“ und „hOCR zusätzlich speichern“. Hier ist die gewählte Sprache ron.

Nach dem Export zeigt die untere Leiste: „PDF gespeichert: … — 3 Seiten, 36 Wörter erkannt“. (Den Export habe ich mit einem Testmechanismus des Programms gestartet, nicht über den Dateidialog.)

Die gemessenen Zahlen (und was sie nicht sagen)

Gemessen wurden 8 gute Seiten einer rumänischen Zeitschrift, gegenüber einem von ABBYY erzeugten Referenztext, der nicht von Menschen korrigiert wurde. Die Fehlerrate pro Zeichen, mit Diakritika (die ursprüngliche Messung, aus der Ausgabe 0.2.0-pre.21; bei einer neuen Messung in pre.26 an denselben 8 Seiten, mit derselben Methode, ergab die native Engine 2,76 %; den Unterschied zu 2,55 % habe ich nicht untersucht):

EngineFehler pro Zeichen
Nativ2,55 %
Tesseract (ron)4,32 %
OCRmyPDF (mit Tesseract)4,62 %

Einfach gelesen: Die native Engine macht bei dieser Druckart weniger Fehler. Aber sie wurde an Text aus denselben Quellen feinabgestimmt, man kann also nicht sagen, dass sie im Allgemeinen besser ist. Bei anderen Dokumenten, vor allem bei altem oder ungewöhnlichem Druck, kann sie schwächer sein als Tesseract. Die Erkennung ganzer Wörter ist zwischen den Engines nahezu gleich (etwa 92 %).

Der genaue Modus und die alte Orthografie

  • --accurate (native Engine): Jede Zeile wird dreimal gelesen (um ein Pixel nach oben und unten verschoben), und die Wahrscheinlichkeiten werden gemittelt. Es ist langsamer (gemessen: 18 % bis 74 % mehr Zeit) und hat nur bei den Zeitschriftenseiten geholfen (Zeichenfehler 3,66 % → 3,39 % bei 12 Seiten); bei Büchern und Broschüren hat es nichts Messbares geändert. Es ist standardmäßig ausgeschaltet.

  • Die Liste rumänischer Wörter akzeptiert auch die Orthografie von 1953–1993 (cuvînt, romîn, sînt): Bei fünf Seiten aus einem Lehrbuch von 1960, von Hand transkribiert, stiegen die korrekten Zeichen von 99,6 % auf 99,7 % und die Wörter von 96,0 % auf 96,3 %. Ein kleiner Unterschied, bei fünf Seiten.

  • Wörter werden an großen Abständen getrennt, auch wenn das Netz kein Leerzeichen geschrieben hat: Die Zellen einer Tabelle kommen nicht mehr zusammengeklebt heraus (CantitatePreț). Eine Tabelle mit Linien wird als eine einzige Tabelle gefunden (Excel: --tables-xlsx); eine Tabelle ohne Linien wird noch immer als zwei Tabellen gefunden (links und rechts), ein ungelöstes Problem.

Tipps

  • Vergleichen Sie bei Ihren eigenen Dokumenten die Engines vor dem Stapel an 5–10 Seiten: scripts/compare-ocr-text.py misst die Fehler gegenüber Referenztexten, die Sie selbst haben.

  • Seiten unter 250 dpi werden vor der Erkennung automatisch vergrößert.

  • Seiten mit Illustrationen oder Diagrammen können im Bildbereich sinnlosen Text erzeugen (Tesseract hat auf einer der gemessenen Seiten eine Illustration als Text gelesen). Prüfen Sie diese Bereiche.

  • Jede OCR kann Wörter erfinden oder verlieren. Bei Urkunden, Registern oder Zahlen prüfen Sie stichprobenartig.

10. So melden Sie ein Problem

Der nützlichste Beitrag ist ein Bericht von einem System, das der Autor nicht ausprobiert hat. Er dauert fünf Minuten:

  1. Laden Sie die neueste Ausgabe für Ihr System herunter.

  2. Führen Sie legatorocr --doctor aus und kopieren Sie die gesamte Ausgabe.

  3. Verarbeiten Sie eine Seite, die Sie teilen können: legatorocr SEITE.jpg --ocr --pdf rezultat.pdf -o pagini.

  4. Öffnen Sie rezultat.pdf: Ist die Seite gerade und richtig beschnitten? Lässt sich der Text markieren und durchsuchen?

Senden Sie als Issue im Repository chiuta/LegatorOCR (oder per E-Mail):

  • das System und die Version (zum Beispiel Windows 11 23H2, macOS 15 arm64, Debian 12 arm64);

  • die Version von LegatorOCR;

  • die Ausgabe des Befehls --doctor;

  • den ausgeführten Befehl (oder die Einstellung in der Oberfläche);

  • was Sie erwartet haben und was passiert ist (Fehlertext oder Screenshot);

  • ob das Bild geteilt werden kann.

Senden Sie keine Dokumente mit personenbezogenen Daten. Ein Bericht „alles hat funktioniert“ ist ebenfalls nützlich: Es ist der einzige Weg, wie der Autor erfährt, dass ein System funktioniert.

Sicherheitsprobleme werden gemäß SECURITY.md gemeldet, nicht öffentlich.
