# LegatorOCR

[English](README.md) · **Română** · [Français](README.fr.md) · [Italiano](README.it.md) · [Español](README.es.md) · [Português](README.pt.md) · [Deutsch](README.de.md) · [Magyar](README.hu.md)

Versiune: 0.2.0-pre.36 · Ultima actualizare: 2026-11-08

Site de prezentare: <https://legatorocr.chiuta.ro> (sursa în `docs/`).

Post-procesor Rust „clean-room” pentru cărți scanate:
**separare → îndreptare (deskew) → decupare → margini → curățare / binarizare → PDF cu strat de text OCR în care se poate căuta.**
Același *flux de lucru* ca instrumentele clasice de prelucrare a scanărilor, dar cod independent. Interfață grafică
(Windows, macOS, Linux) și linie de comandă.

## Pornire rapidă

**GUI** — rulați `legatorocr-gui` (sau deschideți `LegatorOCR.app` pe macOS). Trageți scanări sau un dosar în
fereastră (sau *Add*), alegeți setările din dreapta, verificați previzualizarea **Side by side / Original / Processed**,
ajustați paginile individual (rotire, împărțirea paginii, înclinare manuală), apoi **Export PDF…** sau
**Export images…**. Setările se păstrează între sesiuni; **File → Save project…** păstrează lista de pagini cu
ajustările fiecărei pagini (rotire, împărțire, înclinare, corecția casetei de conținut) într-un fișier text simplu `.lgr`.
Limbi (urmează limba sistemului; se schimbă din meniu): Română, English, Français, Italiano,
Español, Português, Deutsch, Magyar.

**Tur video al ferestrei** — 11 clipuri fără sunet (circa 14 minute în total, cu subtitrări în opt limbi) care parcurg fiecare funcție a interfeței grafice: [docs/video/gui/](docs/video/gui/), sau secțiunea *Tur al ferestrei* de pe [pagina proiectului](https://legatorocr.chiuta.ro/). Filmate pe Linux, cu scanări de probă generate și interfața în engleză; tragerea fișierelor în fereastră este doar descrisă, nu arătată.

**CLI**

```
legatorocr scan_*.png --mode bw --dpi 300 --margin 6 --page-size a5 \
    --pdf carte.pdf --ocr --lang ron+eng
```

Moduri de ieșire: `--mode color|gray|bw|mixed|hybrid`. **mixed** = text 1-bit clar plus zone de imagine color
găsite automat; **hybrid** = același lucru peste un fundal de hârtie cu rezoluție mică
(`--hybrid-dpi`), ceea ce dă pagini de carte color de aproximativ 60–100 KB în loc de 700 KB+.
Mai mult: `--threshold sauvola|wolf|niblack|nick|bradley|otsu`, `--normalize` (uniformizează iluminarea),
`--dewarp` (îndreaptă liniile curbe), `--dewarp-guide "X,Y X,Y …"` (indicați linia curbată prin puncte, fracții 0–1 din pagina îndreptată; se poate repeta; înlocuiește estimarea automată), `--output-dpi N`, `--uniform-size`, `--align top-left`,
`--project FILE.lgr` / `--save-project FILE.lgr`. Fișierele TIFF multipagină sunt citite pagină cu pagină
(`scan.tif#3` indică o singură pagină).

`--skip-blank`, `--skew DEG` (corecție fixă), `--rotate 90`, `--pdf-quality N` (0 = fără pierderi),
`--format png|jpeg|tiff|none`, `--tessdata DIR`, `--psm N`, `--min-conf N`, `--keep-going` (sare peste
intrările ilizibile, cod de ieșire 2) — vedeți `legatorocr --help`. Se poate indica un dosar în loc de fișiere. Rezoluția
este citită din antetul PNG/JPEG când acesta indică 150–1200 dpi (altfel 300; se poate suprascrie cu `--dpi`); rotirea
EXIF a aparatului foto este aplicată, iar transparența este aplatizată pe alb. Numerele din afara intervalului sunt respinse
cu un mesaj clar, în loc să producă dimensiuni de pagină absurde.

## Opțiuni mai rar folosite

`-o, --out-dir DIR` dosarul pentru imaginile paginilor prelucrate · `--no-deskew`, `--max-skew DEG`, `--no-auto-orient`
(pagini așezate lateral), `--no-despeckle` (păstrează petele mici) · `--sauvola-k K` (sensibilitatea alb-negru),
`--picture-sensitivity 0-1` (mixed/hybrid) · `--jpeg-quality N` (cu `--format jpeg`) · metadate PDF
`--subject`, `--keywords` · `--tesseract PATH` (motor extern) · `--burst-gap SECONDS` (cu `--burst`),
`--fuse-max-shift PX` (cu `--fuse-frames`) · `--watch-interval SECONDS`, `--watch-skip-existing` (cu
`--watch`) · `--version`. `--project FILE.ScanTailor` deschide un proiect ScanTailor: lista de scanări și rotirea fiecărei imagini sunt preluate; înclinarea, împărțirea și casetele de conținut sunt găsite din nou (cititorul a fost scris după descrierea formatului și testat pe un proiect făcut manual, nu pe fișiere din fiecare versiune ScanTailor).
Se poate conecta un alt motor OCR: `--engine tesseract --tesseract PROGRAM` acceptă orice program care vorbește linia de comandă a Tesseract și returnează TSV-ul acestuia (șablon și contract: `docs/examples/external-ocr-engine.py`; un model generativ de acolo poate inventa cuvinte, așa că păstrați un om în buclă). Viteza și acuratețea OCR pe propriile pagini: `scripts/bench-real.py DIR` (imagini cu câte un `NAME.txt` de referință; `--partial` pentru referințe care acoperă doar o parte a paginii).
**Puntea ONNX OCR** (`scripts/engine-onnx.py`; Python cu onnxruntime, numpy, Pillow): rulează o pereche PaddleOCR PP-OCR (detector de text DB, apoi un recunoscător CTC) ca acel motor extern, astfel încât un model ales de dumneavoastră să poată fi motorul OCR fără ca LegatorOCR să includă vreo pondere. Modelele le descărcați dumneavoastră, de exemplu modelele de detecție și recunoaștere PP-OCRv6 din lista de modele PaddleOCR convertite în ONNX (`pip install paddle2onnx`, apoi `paddle2onnx --model_dir DIR --model_filename inference.pdmodel --params_filename inference.pdiparams --save_file det.onnx --opset_version 14`; sau un export ONNX gata făcut dintr-un hub de modele), plus dicționarul de caractere corespunzător (în stil `ppocr_keys_v1.txt`: un caracter pe linie; puntea pune blank-ul CTC la clasa 0 și adaugă clasa de spațiu, ca PaddleOCR). Utilizare: `export LEGATOROCR_ONNX_DET=det.onnx LEGATOROCR_ONNX_REC=rec.onnx LEGATOROCR_ONNX_DICT=dict.txt` apoi `legatorocr scan.png --pdf out.pdf --ocr --engine tesseract --tesseract scripts/engine-onnx.py`. Setări (variabila sau același indicator, `--onnx-det/-rec/-dict/-size/-rec-height/-thresh/-unclip/-space`): latura detectorului 960, înălțimea recunoscătorului 48 (32 pentru modelele mai vechi), prag 0,3, unclip 1,5. Casetele sunt aliniate la axe, fără text rotit și fără clasificator de orientare; cuvintele sunt separate la clasa de spațiu folosind pasul de timp CTC (casete aproximative); încrederea este probabilitatea medie de vârf x 100. **Ce este verificat:** doar instalația (cablajul), cu modele ONNX sintetice minuscule (`scripts/test-engine-onnx.py`: conectarea, coordonatele casetelor după redimensionare, decodarea CTC, TSV prin CLI). **Neverificat:** acuratețea recunoașterii cu modele PP-OCR reale (niciunul nu a putut fi descărcat acolo unde a fost scris acest cod) și dacă diacriticele românești (ă â î ș ț) ies corect: depinde de modelul și dicționarul ales; verificați pe propriile pagini cu `scripts/bench-real.py` înainte de a vă baza pe el. Ca orice motor cu model, poate inventa text.
**Familia docTR a punții ONNX (ROADMAP 4.33)**: același script citește modele docTR/OnnxTR, inclusiv recunoscătorul cu cap românesc din `tools/ocr-train/romanian_head.py` (ă ș ț Ă Ș Ț adăugate la un CRNN docTR înghețat). `scripts/get-romanian-doctr-models.sh [mobilenet|resnet] [DIR]` descarcă modelele originale din fișierele de release GitHub OnnxTR, construiește recunoscătorul românesc (`romanian_head.py splice`, necesită python3 cu onnx) și afișează comanda exactă. Utilizare: `export LEGATOROCR_ONNX_FAMILY=doctr LEGATOROCR_ONNX_DET=DIR/db_mobilenet_v3_large-4987e7bd.onnx LEGATOROCR_ONNX_REC=DIR/crnn_mobilenet_v3_small_ro.onnx LEGATOROCR_ONNX_DICT=DIR/vocab_ro.txt` (sau `--onnx-family doctr` etc.), apoi `legatorocr scan.png --ocr --engine tesseract --tesseract scripts/engine-onnx.py`. Detectorul găsește cuvinte (intrare 1024x1024, prag al hărții de probabilitate 0,3), fiecare decupaj de cuvânt este citit la 32x128 cu decodare CTC lacomă (blank = ultima clasă; `--onnx-dict` este vocabularul ca un singur șir), iar scriptul grupează singur cuvintele în linii și coloane, astfel încât TSV-ul să fie în ordinea de citire. Măsurat prin CLI-ul real pe 12 pagini dintr-o revistă românească (referințe ABBYY, neverificate manual; 2 nuclee CPU): db_mobilenet_v3_large + crnn_mobilenet_v3_small românesc, CER GOOD8 cu diacritice 4,26 %, recall exact al cuvintelor 88,2 %, aproximativ 3,4 s pe pagină (opțiunea `resnet`: 3,67 %, 89,6 %, aproximativ 18 s pe pagină); Tesseract `ron` pe aceleași pagini 5,25 %, 91,3 %, 2,7 s pe pagină. Alte tipuri de literă și scanări: nemăsurate. Rezultatul măsurat într-o frază: la egalitate cu Tesseract la eroarea pe caractere pentru paginile de text simplu (mai bun doar acolo unde Tesseract citește o ilustrație drept text), în urmă la recall-ul cuvintelor, o singură revistă, referințe neverificate manual; vedeți ROADMAP 4.36.
Numele din OCRmyPDF sunt acceptate: `-l/--language`, `--force-ocr`, `--redo-ocr`, `--skip-text`, `--deskew` (fără efect, activat
implicit), `--rotate-pages`, `--output-type pdf|pdfa|pdfa-1|2|3`, `-j/--jobs N`, `--sidecar FILE`, `--image-dpi`
(ieșirea se denumește cu `--pdf FILE`; nu există ieșire pozițională). `scripts/check-options.py` listează fiecare opțiune căreia îi lipsește documentația sau un test.

## Instalare

Descărcați arhiva pentru platforma dumneavoastră de pe pagina Releases sau compilați din sursă:

```
cargo build --release          # target/release/legatorocr and legatorocr-gui
scripts/package.sh <target>    # e.g. x86_64-unknown-linux-gnu → dist/LegatorOCR-<ver>-<target>.tar.gz
```

| Platformă | Artefact | Note |
|---|---|---|
| Linux x86-64 / ARM64 | `.tar.gz` (+ `.desktop`) | necesită OpenGL 2+ și X11 sau Wayland |
| Windows x86-64 | `.zip` | necesită OpenGL 2+ (orice driver GPU; sesiunile RDP simple pot să nu îl aibă) |
| macOS Apple-silicon / Intel | `.zip` cu `LegatorOCR.app` | **nesemnat**: la prima pornire, clic dreapta → Open, sau `xattr -dr com.apple.quarantine LegatorOCR.app` |

**OCR funcționează din prima** cu motorul nativ încorporat (`legatorocr-nocr`, Rust pur, fără
instalare; `--engine native`). Citește cele opt limbi ale interfeței cu un singur model plus liste de
cuvinte pentru fiecare limbă. Modelul a fost antrenat pe text sintetic, apoi rafinat pe linii scanate reale dintr-o revistă românească și dintr-un manual din 1960 (scanările nu se află în acest depozit; proveniența și chestiunile de licență încă deschise: `docs/audit/assets-licences.md`): pe pagini sintetice curate și moderat degradate face sub 1 % erori de caractere, dar scanările reale ale unei tipări vechi sau neobișnuite pot fi mai slabe decât
Tesseract. De aceea `--engine auto` (implicit) folosește **Tesseract când este instalat cu limbile
cerute** și revine la motorul nativ în caz contrar; `--engine tesseract` îl impune.
Tesseract (rulat ca program separat; aplicația îl găsește în `PATH`):
`sudo apt install tesseract-ocr tesseract-ocr-ron` · `brew install tesseract tesseract-lang` ·
Windows: `winget install UB-Mannheim.TesseractOCR` (adăugați-l în `PATH`).
Aceste nume de pachete au fost verificate la 2026-11-04 (`docs/audit/ocr-externals.md`): Debian 13 și Ubuntu 24.04 au `tesseract-ocr` și `tesseract-ocr-ron`; Homebrew `tesseract` este 5.5.4 cu doar `eng` și `osd`, iar `tesseract-lang` conține modelele *fast*; pachetul winget rămâne în urmă (5.4.0 din 2024-06). Fișierul `ron` din `apt`/`brew` este modelul mic *fast* (aproximativ 2,4 MB, 2017); modelul *best* (9,6 MB, același an, aceeași istorie a depozitului) se descarcă manual ca `ron.traineddata` din `tesseract-ocr/tessdata_best` în dosarul tessdata (`--tessdata DIR`). Care dintre cele două citește mai bine paginile dumneavoastră nu a fost măsurat aici.
Aplicația caută și în dosarele obișnuite de instalare (Homebrew `/opt/homebrew/bin`, `/usr/local/bin`,
`C:\Program Files\Tesseract-OCR`), astfel că o aplicație pornită cu dublu clic funcționează fără editarea `PATH`.
Fără Tesseract se folosește motorul nativ (comutatorul OCR rămâne activ). O singură comandă pentru toți ajutoarele opționale: `legatorocr --install-modules` (afișează comenzile) și `legatorocr --install-modules --yes` (le rulează).
O compilare **fără modelul de recunoaștere inclus în program** (de exemplu cât timp licența acestuia este nerezolvată, `docs/audit/assets-licences.md`) se face cu `cargo build --release --no-default-features --features lexicon` (adăugați doar `--no-default-features` pentru a omite și listele de cuvinte); întreaga suită de teste trece și așa, `--doctor` raportează atunci motorul nativ ca lipsă, iar OCR necesită Tesseract sau un motor extern.
`--auto-rotate` / caseta OSD necesită în plus `osd.traineddata` (inclus în pachetele standard).

## Flux de prelucrare (pipeline)

| Etapă | Metodă (tehnici standard, de manual) |
|---|---|
| Orientare | energia profilului pe rânduri/coloane în jurul benzii pasului liniilor (0° față de un sfert de tură); opțional Tesseract OSD pentru direcția exactă; sau `--rotate` |
| Împărțirea paginii | rost (gutter) = banda de coloane cea mai goală din centrul unei foi orizontale (`auto` / `middle` / `off`) |
| Îndreptare (deskew) | claritatea profilului de proiecție, căutare grosieră→fină până la 0,01°, rotire biliniară; sau un unghi manual |
| Caseta de conținut | blocuri de cerneală → dilatare → componente conexe; praful și umbrele de la marginea scanerului sunt respinse, numerele de pagină sunt păstrate |
| Margini / dimensiune | margini în mm, dimensiune fixă opțională a paginii cu conținut centrat; tot ce este în afara casetei de conținut este revopsit în culoarea hârtiei |
| Analiză | totul se măsoară pe o copie de ≈150 dpi (o scanare de 600 dpi este analizată pe 1/16 din pixeli); rezultatul este readus la rezoluția completă |
| Dewarp | liniile de text sunt urmărite prin fâșii verticale înguste (vârfurile profilului de rânduri înlănțuite de la o fâșie la alta); ondularea fiecărei linii în jurul propriei înălțimi medii devine un câmp de reeșantionare verticală, interpolat între linii; omis dacă mai multe linii lungi nu arată o curbură clară |
| Iluminare | `--normalize`: culoarea hârtiei pe canal dintr-o copie de ≈60 dpi filtrată cu maxim și estompată, apoi un câștig pe pixel |
| Binarizare | Sauvola (implicit), Wolf, Niblack, NICK, Bradley, Otsu, **auto** (pe pagină: încearcă metodele locale pe o copie de ≈150 dpi și o păstrează pe cea cu cele mai puține pete izolate și o proporție plauzibilă de cerneală), toate din sume glisante pe coloane, cu memorie O(lățime) |
| Curățare | `--invert` (negative: mediană închisă + coadă luminoasă), `--auto-levels` (întindere 0,5 %/99,5 %, un singur câștig pentru toate canalele), `--dropout red|green|blue`, `--punch-holes` (pete rotunde închise de 3–10 mm lângă margine, umplute cu culoarea hârtiei din jur), `--fingers` (regiuni de culoarea pielii care ating marginea, judecate relativ la culoarea hârtiei), `--remove-lines` (linii ≥ 25 mm și grosime ≤ 1,2 mm; tijele literelor care traversează o linie supraviețuiesc), `--sharpen`, `--denoise 0-1` (netezire care păstrează marginile), `--deblur 0-1` (deconvoluție Van Cittert pentru scanări moi) (mască de neclaritate ≈0,3 mm), `--despeckle-strength` |
| Imagini | dale cu o proporție mare de tonuri medii (textul este bimodal, fotografiile sunt continue) sau zone întunecate pline, închise și filtrate după dimensiune → pete de culoare |
| Ieșire | color, tonuri de gri, alb-negru, **mixed** (text 1-bit + pete de culoare) sau **hybrid** (+ strat de fundal cu rezoluție mică); reducere opțională a eșantionării la `--output-dpi`; dimensiune de pagină fixă sau uniformă pentru toată cartea, cu aliniere |
| PDF | scriitor propriu: JPEG (color/gri), CCITT Group 4 pentru 1-bit (revine la Flate când este mai mic), pagini stratificate (mască stencil + fundal + pete); dimensiunea reală a paginii din DPI |
| Imagini (fișiere) | PNG cu rezoluție, TIFF Group 4 pentru alb-negru |
| Probleme ale hârtiei | `--show-through` (uniformizează iluminarea, apoi readuce la culoarea hârtiei pixelii doar puțin mai închiși decât hârtia; cerneala reală nu este atinsă), `--descreen` (dalele de ≈2 mm care sunt în mare parte tonuri medii și încărcate la scara pixelului sunt estompate ușor; dalele de text sunt lăsate neatinse) |
| Foi separatoare | `--split-on-barcode` (paginile care poartă un cod de bare, în poziție dreaptă, rotite la 180° sau lateral, citit pe scanarea brută — Code 128, EAN-13, ITF, Code 39 —, încep un document nou denumit după cod → `book_001_ACT-17.pdf`), `--make-separator TEXT` tipărește o astfel de foaie (PNG A4) |
| Navigare în PDF | `--bookmarks` (o intrare de cuprins pentru fiecare fișier sursă), `--front-matter N` (paginile i, ii, iii … apoi 1, 2, 3 în vizualizatoarele PDF) |
| Zone de ștergere | `--erase X,Y,W,H` (mm de la colțul stânga-sus al paginii, se poate repeta): pictate cu culoarea hârtiei înainte de a se măsura orice altceva; `erase=` în proiectele `.lgr`; câmp de text în GUI |
| Rotire manuală | în GUI, o foaie rotită cu butoanele de rotire (sau ±45°) este blocată: orientarea automată (verificarea încorporată, Tesseract OSD) nu se aplică peste ea, nici măcar la 0°; Reset o redă. În proiecte: `orient-locked = 1` |
| Zonă de lucru și linie de tăiere | `--work-area X,Y,W,H` (mm din scanarea încărcată): tot ce este în afară este pictat cu culoarea hârtiei înainte de a se măsura orice; `--cut-at FRACTION` taie o foaie cu două pagini la acea fracțiune din lățimea ei, în loc de rost sau de mijloc (orice rotire; pe o foaie rotită cu 90° sau 270° cele două pagini ies una deasupra celeilalte). În GUI ambele se desenează sau se trag pe original („Work area”, „Cut line”); `work =` și `split-at =` în proiectele `.lgr`. Testat numai pe foi sintetice |
| Lot | `--skip-duplicates` (pagini consecutive cu o diferență de miniatură 96×128 ≤ 2/255), `--split-on-blank` (paginile goale separă documentele → `name_001.pdf`, …), `--target-size MB` (calitatea JPEG aleasă dintr-un eșantion de pagini astfel încât PDF-ul să încapă) |
| Intrare OCR | paginile sub 250 dpi sunt mărite ×2–×4 (Catmull-Rom) înainte de Tesseract; casetele cuvintelor sunt aduse înapoi |
| Fotografii cu telefonul | `--perspective`: găsește pagina ca patrulater luminos mare (Otsu + colțuri extreme, cu verificări de convexitate/umplere) și o deformează cu o omografie; nu face nimic pentru scanări drepte sau pe tot cadrul |
| Control calitate și arhivă | `--report r.html` (fișă de contact, semnalează paginile goale / cu dimensiune atipică / puternic îndreptate), `--multitiff out.tif` (TIFF Group 4 multipagină, doar alb-negru) |
| Livrare | `--checksums` scrie `SHA256SUMS.txt` (același format ca `sha256sum`) lângă PDF pentru fiecare fișier scris; `--verify-sums SHA256SUMS.txt` le reverifică mai târziu (cod de ieșire 1 la orice nepotrivire sau fișier lipsă); `--rights-notice "…"` stochează o declarație de drepturi (XMP `dc:rights` cu `--pdfa`, altfel cheia de informații `/Rights` și o pictogramă de notă pe pagina 2); `--txt-each` scrie `<nume pdf>.txt` lângă PDF pentru indexatoare precum DocFetcher / Agent Ransack; `--package FOLDER`, `FILE.zip` sau `FILE.iso` (ISO 9660 + Joliet, care se citește pe Windows / macOS / Linux; fără Rock Ridge sau date de pornire; fișiere până la 4 GiB) adună tot ce s-a scris plus `SHA256SUMS.txt` și un `MANIFEST.txt` pentru predare (nu suprascrie niciodată; zip limitat la 3 GiB); `--package-password-file FILE` (sau `-` cu `LEGATOROCR_PACKAGE_PASSWORD`) criptează un pachet `.zip` cu WinZip AES-256; `--audit-log FILE` adaugă o înregistrare JSON Lines pentru fiecare fișier scris (ora, versiunea programului, intrări, SHA-256, dimensiune) cu `--retain-until YYYY-MM-DD` și `--legal-hold` opționale – înregistrează dovezi și nu șterge nimic |
| Fotografii cu telefonul | `--phone-paper A4` (sau `A5`, `B5`, `Letter`, `210x297` …) deduce rezoluția fotografiilor care nu au una din dimensiunea hârtiei, presupunând că cadrul este încadrat pe pagină; o estimare, cu eroare egală cu marginea rămasă în jurul paginii |
| Verificare OCR | Cu `--lang ro`, un avertisment când textul recunoscut are aproape deloc ăâîșț sau multe cuvinte cu litere și cifre (tipic pentru un model românesc lipsă); o notă când `--dpi` este sub 200 sau peste 400 cu `--ocr` |
| Zone de imagine | Păstrate întotdeauna ca imagine color în ieșirea mixed / hybrid, pentru fotografiile pe care detectorul le ratează. Desenate cu mouse-ul în GUI (bifați *Draw zones*, alegeți *Picture*; albastru; Undo / Redo comune cu zonele de ștergere; salvate pe foaie în proiectul `.lgr` ca `picture =`): sunt urmărite prin rotire, împărțirea paginii și îndreptare, deci rămân pe imagine. Nu sunt urmărite prin corecția de perspectivă (atunci sunt abandonate) sau prin dewarp (poziție aproximativă). | Reîncercarea paginilor îndoielnice (nerecomandat) | `--auto-retry` (cu `--ocr`; `--auto-retry-below FRACTION`): o pagină a cărei citire înapoi pare îndoielnică este prelucrată din nou cu alți binarizatori / deskew inversat / alt dpi OCR, iar alternativa cu cel mai bun scor în stil certify este păstrată; `--explain` spune care a câștigat. **Testat și respins:** pe 12 pagini reale nu a schimbat nimic la pragul implicit (2803 -> 2803 erori de caractere) și +25 de erori când este forțat pe fiecare pagină; pe 8 pagini sintetice degradate a ridicat erorile de la 59 la 424 (o pagină înclinată a trecut de la 0 la 354 de erori). Este dezactivat implicit și păstrat doar ca experiment; nu vă așteptați la un beneficiu (ROADMAP 4.24) |
| Preluare | `--ocr-cache DIR` (rezultatele OCR sunt reținute pe imagine de pagină și setări; o nouă rulare omite OCR pentru paginile neschimbate), `--watch DIR` (dosar fierbinte: fiecare scanare nouă este prelucrată după ce încetează să crească; `--pdf` necesită `{name}`), `--burst` (fotografii de telefon ordonate după ora capturii EXIF, se păstrează cadrul cel mai clar din fiecare rafală; listează ce a eliminat), `--scan-active` (listează PDF-urile cu JavaScript, acțiuni de lansare, fișiere încorporate; o privire statică, un rezultat curat nu este o garanție) |
| OCR | casete de cuvinte de la motorul încorporat sau de la Tesseract → strat de text invizibil (mod de randare 3, font Type0 fără glife + ToUnicode, astfel că ăâîșț și orice Unicode se copiază/caută corect) |

Exportul se face în loturi limitate (prelucrare → OCR → scriere), astfel încât o carte color de câteva sute
de pagini să nu trebuiască să încapă în memorie.

Crate-uri: `legatorocr-core` (pipeline) · `-pdf` (scriitor) · `-ocr` (alegerea motorului, driver Tesseract, ieșire hOCR / JSON) · `-nocr` (motor OCR încorporat) ·
`-engine` (orchestrare comună a exportului) · `-cli` · `-gui` (egui/eframe).

Porți de calitate: vedeți `FUZZING.md` (10 suite fuzz/property, rulate săptămânal în CI cu verificări încrucișate qpdf/poppler).

## Export de pasaje

`--passages-jsonl FILE` (cu `--ocr`) scrie JSON Lines: UTF-8, un obiect pe linie, o linie pe
paragraful fiecărei pagini păstrate, paginile în ordinea ieșirii, paragrafele în ordinea de citire a motorului (pe
o pagină cu două coloane, casetele celor două coloane sunt deci listate coloană cu coloană și se pot
suprapune). Paragrafele sunt cele pe care le folosește `--docx` (`words_to_paragraphs`), nu o a doua
detecție. Fiecare cheie este mereu prezentă; o valoare necunoscută este `null`.

| Cheie | Tip | Semnificație |
|---|---|---|
| `schema` | șir | întotdeauna `"legatorocr.passage/1"` |
| `passage_id` | șir, 16 cifre hexazecimale cu litere mici | primele 16 cifre din SHA-256 al lui `"<page_image_sha256>:x0,y0,x1,y1"` (numerele `bbox_px`); aceeași imagine de pagină și aceeași casetă dau mereu același id, unic în fișier |
| `source_file` | șir | numele fișierului de intrare (cu `#N` pentru pagina N a unei intrări multipagină) |
| `page` | întreg >= 1 | numărul paginii în ieșire (după eliminarea paginilor goale și a duplicatelor; un spread împărțit se numără ca două) |
| `page_label` | șir sau `null` | numărul de pagină tipărit, doar cu `--page-labels` și doar acolo unde regula sa de succesiune ar eticheta pagina PDF; altfel `null` |
| `paragraph_index` | întreg >= 0 | 0, 1, 2, ... în pagină |
| `text` | șir, nu gol | paragraful; liniile separate prin `\n`, cuvintele printr-un spațiu. Cu `--clean-text` curățarea se aplică paragrafului, deci textul este cel afișat de `--txt` |
| `bbox_px` | 4 întregi | `[x0, y0, x1, y1]` în pixeli ai imaginii paginii de ieșire, origine sus-stânga, `x1`/`y1` exclusive; `0 <= x0 < x1 <= page_width_px`, la fel pentru y |
| `bbox_frac` | 4 numere | aceeași casetă împărțită la lățimea / înălțimea paginii, 6 zecimale, în intervalul 0..1 |
| `page_width_px`, `page_height_px` | întregi | dimensiunea imaginii paginii de ieșire |
| `language` | șir | setarea de limbă OCR folosită pentru pagină (coduri Tesseract precum `ron+eng`, respectând `--page-lang`); este setarea, nu o limbă detectată |
| `mean_confidence` | număr 0..100 sau `null` | media încrederilor cuvintelor motorului din paragraf, 2 zecimale; `null` dacă niciun cuvânt nu are una |
| `page_image_sha256` | șir, 64 de cifre hexazecimale cu litere mici | SHA-256 al octeților imaginii paginii (vezi `page_image_basis`) |
| `page_image_file` | șir sau `null` | numele acelei imagini în `-o` când a fost scrisă (`--format png/jpeg/tiff`); altfel `null` |
| `page_image_basis` | `"file"` sau `"png-encoding"` | `"file"`: hash-ul este al fișierului imagine scris. `"png-encoding"` (cu `--format none`): nu a fost scrisă nicio imagine; hash-ul este al octeților PNG pe care `--format png` i-ar scrie pentru această pagină |
| `cite` | șir | `"<title> p.<label>"`: titlul este `--passages-title` sau numele fișierului sursă fără extensie; eticheta este `page_label`, altfel `page` |

Verificați un fișier (doar Python din biblioteca standard): `python3 scripts/check-passages.py out.jsonl [--txt out.txt] [--images DIR]`.
Verifică fiecare cheie și tip, că fiecare casetă se află în interiorul paginii sale, fracțiile, hash-ul id-ului, forma
`cite` și, cu `--images`, hash-urile imaginilor față de fișierele scrise; cu `--txt`
compară pasajele fiecărei pagini cu aceeași pagină din ieșirea `--txt` (spațiile
albe comprimate) și afișează procentul de potrivire. Formatul este propriu LegatorOCR; dacă un anumit
instrument de cercetare (de exemplu TEZAUR) îl poate importa nu a fost verificat.

## Asistent de captură cu telefonul

`web/capture/index.html` este un singur fișier HTML offline (fără cereri externe, fără stocare, fără telemetrie; engleză și română, șirurile într-un singur obiect). Deschideți-l pe un telefon (o cameră necesită https sau localhost în majoritatea browserelor; `file://` funcționează în unele), porniți camera, așezați pagina pe o suprafață mai închisă. Găsește pagina luminoasă (prag Otsu, cea mai mare regiune conexă, colțuri după x+y / x-y extreme, deci până la aproximativ 45 de grade de rotire), desenează conturul și fotografiază singur când conturul a stat nemișcat 0,8 s și pagina trece verificările; în caz contrar spune de ce: nicio pagină găsită, pagina nu este vizibilă complet, prea neclară (varianța laplacianului), prea întunecată, prea luminoasă. Un buton manual, o bandă de miniaturi cu ștergere și „Save burst as ZIP” (ZIP „stored” scris de mână) dau `burst-YYYYMMDD-HHMMSS.zip` cu `page-0001.jpg`, `page-0002.jpg`, ... la rezoluția fluxului camerei (un cadru video, nu neapărat rezoluția completă a senzorului pentru fotografii). Fiecare JPEG poartă o oră de captură EXIF, la cel puțin 4 s după cea precedentă, astfel încât `legatorocr --burst` (implicit `--burst-gap 3`) să păstreze ordinea și să nu ia două pagini drept o singură rafală. Apoi: `legatorocr --burst --pdf book.pdf page-*.jpg`.
Testat doar pe cadre **sintetice** în Chromium headless cu o cameră falsă (`scripts/test-capture-assistant.py`): eroare de colț 1,0-2,1 px la lățimea de 640 pe 6 poziționări (rotire de la -14 la +31 de grade, deplasări, o trapezoidală), refuzurile se declanșează cu motivul corect, ZIP-ul trece `zipfile.testzip` și `unzip -t`, iar `--burst` acceptă paginile dezarhivate. **Netestat:** telefoane reale, iluminare și umbre reale, neclaritate de mișcare, autofocus, iOS Safari, un birou luminos sau alb (pagina se contopește atunci cu fundalul), refuzul „too bright”. Toate pragurile sunt presupuneri nereglate.

## Indicii de integritate (`--integrity-hints`)

**Risc RIDICAT de alarmă falsă. Citiți aceasta înainte de utilizare.** `--integrity-hints FILE.json` (opt-in, rulează pe imaginile de intrare așa cum sunt, înainte de orice curățare) scrie, pe pagină, casete în pixeli de pagină pe care o persoană ar putea dori să le reverifice, fiecare cu un „ce înseamnă” și „cauze nevinovate frecvente” în limbaj simplu. Este o listă de lucruri *de verificat*, niciodată un verdict; ieșirea nu spune că un document este autentic sau nu. Nu o folosiți ca unic temei pentru nicio decizie privind o persoană sau diploma unei persoane; întrebați instituția emitentă.

Semnale (`--integrity-signals LIST`; `all`, `default` sau nume):

| Semnal | Se uită la | Rulează implicit |
|---|---|---|
| `copy_move` | blocuri 16x16 identice (cu hash; hârtia goală și glifele repetate de mai multe ori sunt ignorate) în două locuri, la orice decalaj de pixeli; casete de cel puțin 64 px pe ambele laturi | **da** |
| `jpeg_grid` | intrări JPEG: o fereastră de 128 px al cărei tipar de margini de blocuri 8x8 este decalat față de restul paginii | nu: 4 din 12 pagini needitate semnalate, 0 din 60 de editări găsite |
| `jpeg_double` | intrări JPEG: tiparul în pieptene al unei a doua salvări (statistica `--verify-document`, pagină întreagă) | nu: nicio alarmă falsă, dar 0 din 60 de pagini editate semnalate în testul de mai jos |
| `noise` | dale al căror zgomot fin este de 3 ori mediana paginii | nu: 10 din 12 pagini needitate semnalate |
| `line_size` | necesită `--ocr`: un cuvânt a cărui înălțime sau poziție nu se potrivește cu linia lui de text | nu: 12 din 12 pagini needitate semnalate |

Măsurat doar pe editări **sintetice** (12 pagini reale din setul de test OCR, JPEG q85; editări: un șir de cifre desenat peste un cuvânt, un petic de 220x140 copiat în altă parte, un petic de 260x180 dintr-o copie q45 lipit la un decalaj ciudat, zgomot gaussian în 240x160; fiecare pagină editată re-salvată la q85; iar paginile curate salvate o dată, re-salvate o dată la q85, re-salvate din nou la q75; `docs/experiments/integrity_eval.py`, ROADMAP 7.5c). `copy_move`: a găsit 10 din 12 petice copiate, 0 din 36 de pagini needitate/re-salvate semnalate; **nu** găsește o cifră sau un cuvânt retipărit și ratează peticele mai mici de 64 px. Limita de dimensiune a fost stabilită după ce s-au văzut alarme false pe aceleași pagini, deci cifra este optimistă. Aceste numere nu spun nimic despre falsurile reale, care sunt făcute cu alte instrumente, alte fonturi și altă compresie; ștampilele reale, siglele repetate și antetele de scrisoare nu au fost în test și sunt sursa așteptată de alarme false. Celelalte semnale sunt disponibile cu `--integrity-signals all`, doar pentru cercetare.

## Limite cunoscute

Vedeți `COMPARISON.md` pentru ce fac alte instrumente și acesta nu. Pe scurt:

- **Orientare**: testul încorporat găsește doar „pagina stă pe o parte”, nu *în ce sens*. **Orientarea prin OCR**
  (comutator GUI / `--auto-rotate`) rezolvă 90° față de 270° și paginile cu susul în jos: cu datele `osd` ale Tesseract când sunt
  instalate, altfel cu motorul încorporat, care citește o copie redusă în toate cele patru rotiri și o păstrează pe cea ale cărei
  cuvinte se găsesc în listele de cuvinte ale limbii (necesită vreo douăsprezece litere de text tipărit; altfel pagina este lăsată
  neatinsă). Alternativă manuală: *Rotate left/right 90°* / `--rotate`.
- Zone de ștergere: tastate în milimetri (aceleași pe fiecare pagină) sau desenate cu mouse-ul pe foaie (trageți pe vizualizarea Original, clic dreapta elimină; stocate în proiect); zonele de imagine se desenează la fel (albastru); la fel și liniile de ghidaj dewarp (de mână liberă, tipul *Guide line*; tastate și prin `--dewarp-guide` / câmpul din GUI). Desenarea din GUI nu a fost testată vizual.
  Imaginile sunt detectate și automat
  (sensibilitate reglabilă), iar caseta de conținut poate fi deplasată pe pagină (câmpuri numerice sau tragând marginile ei verzi în GUI; pe un spread împărțit deplasarea se aplică ambelor pagini).
- Dewarp corectează doar curbura verticală a liniilor de text (fără perspectivă / întindere orizontală).
- `--pdfa` scrie *structura* PDF/A-2b (font text TrueType încorporat fără glife, pachet XMP care corespunde dicționarului Info, profil sRGB de intenție de ieșire încorporat, gri bazat pe CIE, ID în trailer). Fontul, profilul ICC și XMP au fost verificate cu fontTools, LittleCMS și un parser XML, iar fișierul cu qpdf și poppler, iar jobul CI `PDF/A validation` rulează veraPDF (greenfield 1.30.x, profil PDF/A-2b) peste fișiere de probă generate — alb-negru, mixed, hybrid, gri, cu și fără strat OCR, una și două pagini — și eșuează când oricare este respins. Aceasta este un test al acelor probe, **nu o certificare** a fiecărei ieșiri posibile. Intrare PDF: decodarea Huffman JBIG2 verificată față de pdfium pe fluxuri generate (varianta cu hartă de biți colectivă MMR doar față de propriul nostru decodor G4, pdfium o randează goală); rafinarea/agregarea Huffman (rafinarea regiunii de text, simboluri rafinate și agregate; tabele personalizate) verificată față de poppler și, cu excepția decalajelor de rafinare RDW/RDH în afara intervalului -2..1, față de pdfium (pdfium centrează referința cu RDW>>2 în loc de RDW>>1 în regiunile de text Huffman și decodează greșit cazul de aceeași dimensiune, decalaj zero; poppler și decodorul nostru urmează standardul), simbolurile rafinate goale din dicționarele agregate Huffman fiind refuzate; stilurile de bloc de cod JPEG 2000 inclusiv bypass/termall, POC, PPM și PPT au fost verificate față de OpenJPEG 2.5 pe aproximativ 1.350 de fluxuri generate (fără pierderi exact, 9/7 în limita a 2 niveluri de gri; fluxurile PPM/PPT au fost produse rescriindu-le pe cele ale OpenJPEG, pe care OpenJPEG le-a decodat apoi identic), paletele JPEG 2000 și stilul de bloc de cod de mare debit (Part 15) nu sunt acceptate, predicția tipică JBIG2 pentru regiunile de rafinare (TPGRON) și grilele de semitonuri deplasate verificate doar față de propriul nostru codor (poppler le decodează diferit); fișiere criptate: parolele utilizatorului și ale proprietarului au fost verificate pe fișiere făcute cu qpdf (RC4-40/128, AES-128, AES-256 R5/R6); coduri de bare: Code 128 (seturile A/B/C), EAN-13, ITF, Code 39 sunt citite, doar Code 128 este tipărit. JBIG2 și Group 3 au fost verificate față de ieșirea poppler / libtiff; compunerea paginilor stratificate doar față de paginile scriitorului nostru.
- Corecția de perspectivă necesită o pagină clar mai luminoasă decât împrejurimile și care arată toate cele patru colțuri; altfel lasă fotografia neatinsă. Nu desfășoară paginile curbe (folosiți `--dewarp`).
- Eliminarea pielii/găurilor/degetelor sunt euristici: `--fingers` este dezactivat implicit și poate consuma fotografii de culoarea pielii de la marginea paginii.
- DPI este citit din antetele PNG/JPEG (150–1200 dpi; 50–149 doar când dimensiunea implicită a paginii este plauzibilă, și niciodată 72/96, pe care editoarele le scriu implicit), dar nu din antetele TIFF: setați `--dpi` manual când aveți îndoieli; TIFF pe 16 biți este redus la 8 biți.
- Înclinare: paginile aproape fără cerneală sunt lăsate cum sunt, iar când rândurile de text și structura verticală dau amândouă un unghi clar, dar diferit (desene oblice, hașuri), pagina nu este rotită. Paginile care sunt deja singure și drepte ar trebui prelucrate cu `--split off`.
- O margine întunecată a patului scanerului *care atinge* textul poate încă mări caseta de conținut detectată
  (marginile și umbrele de colț separate de text sunt eliminate).
- Compilările pentru Windows și macOS provin din fluxurile de lucru CI (`.github/workflows`); mediul de
  dezvoltare al autorului a verificat doar Linux.
- Release-uri: **Actions → Release → Run workflow** (introduceți un tag precum `v0.2.0-pre.1`) sau împingeți un tag
  `v*`. Fluxul de lucru rulează mai întâi toată matricea CI, apoi construiește toate cele cinci platforme și deschide un
  pre-release **ciornă** pentru revizuire; nimic nu este publicat până nu apăsați Publish.
